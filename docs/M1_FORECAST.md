### 2.2 固定运行包

安装包采用 **源码副本 + 已构建前端dist + 独立锁定依赖 + release清单**，不新增Node bundler。

`runtime/package.json`把实际运行需要的tsx、Zod声明为正式依赖；精确版本从已审查的项目锁文件确定。本轮不顺带升级。运行锁文件包含全部传递依赖及平台依赖，不把“两个直接依赖”误称为只有两个安装文件。

在临时发布目录执行独立 `npm ci`，成功后校验、试运行，再封存为不可变release。不得使用开发目录的node_modules、NODE_PATH或依赖软链接。npm ci依赖已存在且匹配的锁文件，不在安装时自由解析新版本。[R2]

必须明确三个根：

```text
code_root     当前固定release的代码和依赖
data_root     本项目唯一生产档案根，继续读取原有artifacts结构
runtime_home  安装状态、稳定启动器、release目录与current.json
```

安装配置显式关联三者。源码哈希在code_root校验，行情/原档引用在data_root解析；相对旧来源路径由受控兼容解析器解释，禁止用artifacts软链接绕过路径校验。data_root指向实际artifacts目录；现有引用中的artifacts/前缀由兼容解析器规范化一次，不能重复拼接或允许..逃逸。原始数据不随release复制或回退。运行包不执行git rev-parse；构建时将Git身份写入manifest。

稳定启动器只解析安装配置和原子更新的 `current.json`，一次任务只选定一次release。启动器本身纳入安装校验和备份；官方任务引用稳定入口，不跟随未提交开发源码。

### 2.3 单一发布清单与信任边界

`runtime/files.json`由代码审查维护，打包器、运行校验与doctor共用；它覆盖所有实际运行入口、间接源码、模板、配置、兼容实现和静态资源。CI检查导入闭包以及清单漏项，不只是检查“列出的文件存在”。

每份release保存：Git提交、源码清单哈希、运行锁文件哈希、安装依赖清单、Node/平台、CLI适配版本、允许的预测/校准/反馈策略、测试记录及实际批准来源。内容清单不自包含自身哈希；release ID根据约定的规范化清单计算，批准收据独立绑定该ID。

校验和值证明内容对应关系，不替代维护者批准。不得自行重写批准哈希使改动通过。

### 2.4 展示服务

使用Node内建HTTP服务，复用展示读取器与请求校验。Vite仅供开发和前端构建；不以代码行数限制服务器实现。

生产静态构建只允许前端资源和许可证，排除 `public/data` 及DEMO真实快照。HTTP仅绑定 `127.0.0.1`，使用安装时确认的固定端口。保留Host/Origin/Referer、路由和方法白名单、大小限制、路径穿越/符号链接拒绝、敏感字段裁剪。API只读；静态文件按manifest白名单提供；模型文字用textContent，不直接执行HTML。

### 4.5 精确slot、截止与补跑规则

计划的奇数小时47分对应锚点为同小时45分，首未来节点为下一整点。`slot_id`采用产品、15m、24h和锚点UTC组成，不包含方法/release，防止换版本绕过去重。该slot的起止规则必须写进配置和测试。

```text
cycle_deadline = 实际业务入口开始 + 600秒
publish_deadline = min(cycle_deadline, anchor + 900秒 - 30秒)
attempt_timeout = min(240秒, publish_deadline - now - 收尾预算)
```

预算用单调时钟计时，并在发布前重新检查真实UTC首节点。发现时钟跳变或重大服务时间偏差，拒绝把可疑输出当及时发布。旧核对最多45秒且不能用尽生成窗口；每次模型调用开始前至少保留90秒可用预算，否则 `SKIPPED_BUDGET`。

调度延迟不能通过移动锚点掩盖。超过该slot窗口，不生成该期预测，只登记 `MISSED_WINDOW`。恢复休眠后可以补旧预测的实际行情，不能补造过去预测。下一正式预测等待下一个合法slot。

手动试运行也要归属当前可用slot；已有发布时返回同一份，不另生成。需要额外测试输出时只进隔离测试/明确研究角色，不混入生产统计。manual、scheduled、bootstrap的真实身份分开记录，不编造官方thread。

### 4.6 失败重试矩阵

| 故障 | 行为 |
|---|---|
| HTTP超时、短暂连接失败、5xx | 最多3次总尝试，2秒/5秒退避；每次均受剩余预算限制；已成功页不无故重下 |
| HTTP 429 | 尊重可用Retry-After且不越过截止；超预算则下次合法任务再取，不连环重试 |
| 认证失效、配置非法、权限拒绝、身份/完整性不符 | 本轮不重试，准确告警；不改认证或扩大权限绕过 |
| 模型进程失败、输出格式/类别校验失败 | 同run、同冻结输入最多2次；失败原文保留；不重取行情换锚点 |
| 模型超时或结果不确定 | 该attempt计入预算并留不确定/超时收据；确认受管进程退出后，剩余配额与截止允许才继续 |
| 发布已完成，索引或报告失败 | 不重新调用模型；后续重建索引/报告；保留有效publication |
| `BUSY`，确认另一合法业务正在执行 | 写本次独立观察记录后退出，不抢写共享status，不等待重入 |
| `MUTEX_CONFLICT`，端口占用身份未知 | 立即诊断/告警，不kill、不自动换端口；后续巡检继续报告相同故障键 |
| 缺少部分真实K线 | 保留partial/missing_data和游标，下次ops补采；不用0或插值伪造完整评分 |
| 候选失败/预算跳过 | 保留预登记机会及原因；正式结果不撤销；不在当天换机会重抽 |
| 备份盘离线/空间不足 | 不在挂载点下偷偷创建本地替代目录；保留上次备份，报告阻塞 |

### 4.7 幂等与并发

任务触发ID、业务slot、模型attempt、数据capture和评分revision分开建模。

- 正式预测：在业务互斥下为slot创建独占记录；同slot重复入口返回已完成结果或原恢复状态。开始模型后不因崩溃新建run重新抽样。
- ops：`task_key + UTC计划小时`去重；中断可以按对象游标续接，不重复完成的副作用。
- 评分：按forecast哈希、可比观测内容哈希、scorer版本确定结果；请求收据变化不扩大统计样本。
- 案例：run与evaluation revision绑定；新修订新增，不覆盖旧反馈使用的版本。
- 决定：实验ID与唯一检查点只生成一次；当前策略指针下一次冻结才生效。
- 备份：内容对象按哈希去重，快照manifest不可覆盖；未提交临时对象不标为成功。

最多一个生产数据写者；ops、手动核对、策略切换、短备份快照捕获均走同一个写入入口。只读巡检与HTTP读取不占写锁。不能把网络调用的“恰好一次”当作保证；以持久attempt和提交记录实现本地去重。

### 4.8 日志、告警和状态

每次入口在争锁前写独立 `observations/<task>/<invocation_id>/started.json`，结束写独立result；真正的持锁者更新自己的cycle。`status.json`是可重建摘要，不是所有进程竞争覆盖的日志。

字段至少包括：task逻辑键/真实注册ID、trigger、可取得的真实thread、计划slot与实际开始、步骤、耗时、重试数、release、行情截止、publication/revision、错误码和可重试性。日志逐轮新目录，公开摘要不包含prompt/raw、凭证或私有路径。

页面按任务分别显示最近尝试、最后成功、实际数据截止、活动轮次、暂停意图、阻塞原因、健康检查时间。备份成功不能刷新“最近预测成功”。配置ACTIVE不等于有新产出；预测未过24h也不等于两小时更新正常。每个预期slot在首未来节点后2分钟仍无及时有效publication，状态变为更新停滞；这是按配置推导的缺产出状态，不是虚构一次实际失败调用。暂停期间不累计预期slot缺产出告警。

| 条件 | 告警动作 |
|---|---|
| 内容完整性错误、未知互斥占用、权限/认证失效、存储无法写入 | 首次立即告警，阻断受影响动作 |
| 单次普通网络失败或预算跳过 | 页面记录；到期没有及时新预测则标更新停滞 |
| 连续两期预测失败/错过，或巡检连续两轮未取得必要结果 | 发一次异常摘要，附最后成功和唯一建议动作 |
| 巡检自身超过90分钟无新观察 | 页面标“巡检信息陈旧”；不能显示实时健康 |
| 同一故障持续 | 以task+错误码+对象去重；默认6小时最多提醒一次，严重性升级除外 |
| 故障恢复 | 发一次恢复摘要；保留故障历史 |
| 明确暂停 | 显示暂停，不反复当故障告警 |

通知先使用已启用的官方任务通知和本地摘要，不擅自接Telegram/邮件新服务。官方渠道不可用时保留outbox及未发送状态，不把落盘当已送达。所有本地任务均停止运行时，本地系统不能立即通知断电故障；恢复后的第一次巡检报告观察空白，不能伪造停机期间的执行记录。

### 4.9 官方任务正文要求

**m1：** 只运行稳定启动器的forecast入口，使用真实触发身份；不要执行开发工作流，不自行查新闻、生成聊天版替代预测或重复调用模型；读取脚本结果，只报告新异常和必要摘要。

**m1-ops：** 只运行ops入口；读取结构化结果；不得触发预测、修改提示词/源码、操作Git、清理未知进程；故障按outbox去重。

**m1-backup：** 只运行backup入口；周日由同一脚本决定执行restore-check；不能改源档、删除旧备份或上传真实材料到GitHub。

**chart-mvp：** 读取AGENTS、当前Issue和最新审查；优先续接检查点；一个写入者、一个已放行任务；自测和提交按第10节；不得将自己的报告当成批准。

任务设置后必须回读：真实ID、正文hash、执行目录、运行模式、时区/等价触发规则、启停状态、配置读取时间。无法回读的项明确未知。首次切换分别保存未来三次计划时点与UTC换算，和工具实际返回值交叉核对。官方下一次执行时间与本项目按规则计算的预计时间分字段存储。

## 5. 业务互斥与受管进程恢复

业务采用贯穿完整轮次的Node进程，通过安装时确认的127.0.0.1固定端口互斥。禁止reusePort和把监听句柄传给子进程；owner文件只做诊断，端口占用不以文件年龄判断。开发executor锁仅保护源码与Git。

业务owner绑定随机token、项目/数据根、release、PID、进程启动身份、主机/启动身份以及受管子进程。生成CLI在可识别的进程组中运行，原始输出只写对应attempt；只有仍持有业务互斥且token有效的父流程能提交publication。

正常退出、取消和超时先停止本轮网络请求，对能够证明属于本轮的子进程发送SIGTERM，短暂等待后才SIGKILL。禁止全局kill codex/node、仅按进程名杀进程或按端口杀未知应用。

父进程死亡不证明子进程已退出；Node文档也说明子进程可能在父进程结束后继续运行。[R4] 下一轮必须核对未完成attempt、受管进程身份和已提交publication。能确认的孤儿受控终止并留记录；无法确认则阻断相关写入并报告，而不是只因为端口已释放就当恢复完成。

恢复不能把旧running改为成功。追加recovery记录，注明未完成步骤及是否允许继续；如果publication已经提交则修复后续指针，不重复生成。历史开发逻辑锁不可用已经退出的acquire短命令PID判死。

## 6. 数据输入、模型与历史兼容

### 6.1 市场与衍生品输入

每个新预测独立取得完整1344根已收盘K线及原始分页；分页有上限但不把上限写成实际页数。确认连续、时间单位、确认标记、重复与冲突处理。不能使用旧预测快照冒充本次最新输入。

正式方法与候选共用一次冻结的市场快照：包括K线、特征和本轮可用附加输入的内容与来源哈希。两个方法的prompt可以不同，行情锚点和评分目标必须相同。核对多个旧run可以复用同轮已下载的实际区间，但各run仍按自身锚点裁切和保留来源引用。

OI/funding使用OKX公开接口，至少接通open-interest、funding-rate、funding-rate-history；具体参数、单位、限流和字段以实施时官方文档核实，不增加账户API。[R5]

保存原始响应、provider timestamp、received_at、frozen_at、产品、计量单位与质量状态。区分OI张数/币数量/美元名义量，区分待结算费率与已结算历史。结算间隔来自响应，不固定假设8小时。没有历史OI观测就不能计算历史变化；缺失不填0。

预测前新取的快照可能晚于K线锚点，必须如实记录真正信息截止；这不改变目标节点或首次发布时间条件。前向/回放仅使用当时实际可获得的输入。

### 6.2 官方事件日程

只接入BLS CPI日程、Fed FOMC日程及其必要官方链接，不做泛新闻爬取。[R6][R7]

日历抓取有域名白名单、响应大小和超时限制；默认TTL6小时、最大允许缓存年龄12小时。过期或解析失败时保留来源与原因，使用事前允许的market_only变体，不等待日历无限阻塞预测。

每条事件区分 `source_published_at`（可空）、`first_seen_at`、`fetched_at`、`event_time`或日期范围、时间精度及解析器版本。来源明确提供美东时区时按America/New_York处理DST；只有日期的FOMC日程不能硬造精确到分钟的公布时刻。转换实现必须通过DST和跨日金样，不能误认为Intl本身提供任意本地时间字符串解析。

零个纳入事件时使用market_only，保存已解析但排除的items及原因；同时区分“窗口内没有可纳入事件”“来源未取得”“解析失败”。至少一个合法事件真正进入输入后，才使用official_calendar。

现有事件验证对纳入项要求published_at。能满足现有语义时复用；来源未给该时间但已有first_seen证据的场景，使用一个明确的新事件契约，允许published_at为空并以真实观察时间证明可用性。不能把抓取时间填成来源发布时间，也不能简单删除检查。已有档案仍按原契约读取。发布时间精度不足的日期范围输入保持该精度。

采集完成不等于已用于正式方法；页面分别列“已取得”和“本次实际纳入”。附加数据通过有限的单因素候选实验逐步启用，不同时更换多个因子后宣称知道改善原因。

### 6.3 模型配置与输入隔离

生成policy显式包含已获准model、reasoning effort、输出契约和工具使用约束。按实际安装的CLI帮助和受支持配置显式传参；保留现有官方登录，不复制凭证、不接新API。外层调度模型与内层生成模型分别记录，不因名字不同自动提升推理预算。

审计保存请求配置、实际参数、CLI版本、执行目录、可见thread和提供方实际返回的身份字段。未返回服务端身份则为空，不拿配置名冒充证明。

无关全局偏好变化只作doctor诊断；影响provider、模型、工具权限、网络和冻结输入隔离的配置仍必须检查。调用前冻结全部输入，期间禁止模型联网、读其他档案或正式答案；审计工具事件。只拒绝有业务意义的不兼容事件，已知安全启动通知通过有测试的版本适配处理，不泛化放过未知工具执行。

### 6.4 历史读取和算法身份

保存并区分：数据内容哈希、classifier/scorer/predictor语义版本、实际代码build_id。先建立真实只读回放记录及可公开的SYNTHETIC金样，再修改契约。

兼容模块覆盖影响语义的依赖，包括契约、分类、评分及必要投影；建立明确的已知版本/来源哈希到受审查实现的映射。不是仅复制两个函数后删除源码校验。

读取链必须验证：冻结文件集合、来源内容、raw输出、程序转换、发布时间、publication、capture和evaluation。最终概率允许程序修正，但必须由原始概率与冻结参数可重建；不得破坏raw与发布结果的对应关系。

未知语义版本不参与评分、学习和晋级；在能够安全验证原预测内容的情况下可受限展示原预测，并标“此评分版本当前无法重算”，不把整份原预测一律当丢失。新算法的重算产生新revision，原结果保留。

## 7. 核对、反馈和方法改进

### 7.1 评分口径

六类规则与阈值保留。概率只对应完整24小时事件，不随6h/12h图表裁切而换含义。

```text
Brier = Σ(k=1..6) (p[k] - y[k])²                  范围[0,2]
平均Brier = Σ各合格预测的Brier / 合格预测数量
path_loss = mean(|predicted_close - actual_close|) / anchor ×100
改善贡献 = 同机会参考方法损失 - 当前方法损失
```

不除以类别数量6。需要0–1显示可额外提供明确标注的Brier/2；它不是准确率。多分类Brier的该定义与标准实现一致。[R8]

主情景在发布时按最终概率最大值固定，平手按冻结类别顺序；同时保存原始概率主情景。六条路径各自误差保留，不事后挑最像的一条。提供0–6、6–12、12–24小时及完整路径诊断；保留恒价参考。不用时间轴伸缩掩盖转折时点错误。

阶段范围只报告原定义下的覆盖、宽度和偏离，不假称80%预测区间；暂不新增强制分位数。24h必须96个目标收盘节点齐备才评分；partial可显示实际线，missing为null，late不进入正式前向成绩。

全量重叠run可用于描述；正式方法比较使用预登记的非重叠目标窗口。非重叠也不被称为已经证明独立。发布数量、合格成熟评分数量、前向配对窗口数量分开展示。

### 7.2 案例与污染控制

案例采用版本化 `MFV:M1_CASE:v1`。只从原预测合格、完整24h、哈希链通过、按对应scorer重算一致的revision生成。还必须满足该scorer未被禁用、未命中已知问题或撤销清单。

重算一致只证明实现重复一致，不证明公式绝无bug。因此CI保留独立手算金样和边界测试；发现评分缺陷时禁止新案例/晋级，隔离受影响revision。历史反馈包保持原字节，修正只影响后续输入。

案例包含原特征、raw/final概率、固定主情景、实际类别、各类损失/基准、诊断标签、来源revision、首次可用时间。`available_at`至少晚于来源结果、评分和案例真正提交的时间；当前补采的历史结果不能倒填可用时间。

反馈最多4个相关案例、8KB UTF-8，采用现有数值特征的确定性相似检索；标准化只用当时可用历史。零尺度维度跳过，缺数不编造，相关失败案例可纳入但不强塞不相关正反例；同一行情机会不重复讲述。附近期整体统计，精选案例不能直接当类别频率样本。

冻结case IDs/revisions、检索/摘要构建器版本、确切反馈正文和hash。再次消费案例时执行严格验证，而不是永久相信显示缓存。加入未来才可用案例不能改变已经冻结的输入。

提供受控 `learning disable`：后续采用基础反馈策略与lambda=0，记录生效时间及首个run；不改源码、不覆盖历史、不伪装成性能回退。

### 7.3 概率修正

```text
b[k] = (历史合格非重叠窗口中第k类数量 + 1) / (N + 6)
p_final[k] = (1 - lambda) × p_raw[k] + lambda × b[k]
lambda ∈ {0, 0.10, 0.25, 0.50}
```

b仅用本次冻结前实际可用、目标窗已结束的历史；按事先固定的时间顺序选择非重叠窗口，最多最近90个，一个行情机会只计一次。输入保存样本ID、counts和基准版本。N=0自然为等概率；未通过前向比较时lambda=0，保留原概率。

同一predictor、生成配置和输入策略至少20个合格非重叠训练窗口，才能在预设lambda中拟合；平手选择较小lambda。训练必须使用各历史预测当时已冻结的b，不能为旧档补造事前基准。拟合只用过去，候选在随后新机会中验证；实验期间lambda不随每天表现重拟合。

概率修正可能改变主情景；raw/final主路径损失都保存，不能以Brier改善掩盖主路径退化。候选拟合和后处理不新增模型调用。

### 7.4 有限候选与前向验证

任何时刻只运行一个正式候选实验。预置基础F0、加入已验证案例的F1，以及经本轮开发和测试允许的附加输入开关；每个实验只改变一个因素。先运行反馈对照，再按新成熟数据决定是否开展概率修正或附加数据实验，不启动组合爆炸的自动搜索。

需要模型的候选机会默认为每天01:47的预测slot；与上个登记目标窗不重叠，正式/候选输入在任何本轮输出出现前共同冻结。正式输出优先及时发布，候选仅用剩余预算；候选单次attempt、每日最多一次。当天错过不能挑另一份更好看的结果补入。候选失败、预算跳过、late和数据缺失保留在登记分母。

实验计划保存双方精确版本、唯一变化、训练截止、机会日历、目标、护栏、预算、检查点。运行期间任何相关模型/输入策略变化，使实验暂停或结束为版本变更，不静默混合。

| 项目 | 起步规则 |
|---|---|
| 检查点 | 第20个完整前向配对可用后检查一次；使用事前规定的前20对 |
| 机会上限 | 最多30个已结束登记机会；不足20对则证据不足，保留现行方法 |
| 主要目标 | 候选平均目标损失至少比正式方法降低5% |
| 时间稳定性 | 按时间前10/后10，两段均不劣于正式方法 |
| 反馈/附加输入候选目标 | 主路径误差；Brier不得退化超过绝对0.02 |
| 概率候选目标 | Brier；最终主路径误差不得退化超过5% |
| 可靠性 | 已启动候选及时有效率至少90%；总登记机会/启动数/完整配对同时展示 |
| 晋级 | 仅本release允许的策略，生成不可变决定，下一次冻结生效 |

以上是固定的工程换版规则，不叫统计显著性，也不等于准确率提高5%。零参考损失用绝对差和数值容差处理，不能除零或把相等称为改善。必须和同机会用户实际使用的完整正式配置比较，不只赢一个没有正式修正的弱基准。

每天至多一个比较机会意味着20对需要至少20个登记机会及最后窗口成熟；没有固定日历日期的必胜承诺。期间继续产出、核对和反馈，不降低门槛凑结论，不持锁等待。

晋级后保留上一策略作为同预算影子对照，使用新的配对窗口和同一判定函数判断回退。一次回退后停止该对方法自动反复切换；后续改进回到有新假设的开发任务。代码、分类规则、评分公式不由业务任务自动改写。

## 8. 页面、可观测性与读取性能

正式页提供四块：最新预测、本次依据、核对与近期成绩、历史与方法进化。时间以年月日为主，同一天多期用简短时分区分；后台UTC与精确时间不删。

默认follow_latest，新publication切换主图；同run新revision更新实际走势和核对。history_pinned保留所选历史，不被新预测抢走；该历史的核对仍可更新。刷新按钮读取索引、详情、核对和runtime，不触发模型。

页面可见时每60秒查轻量版本，隐藏时暂停；恢复、网络恢复和BFCache返回检查一次。使用请求序号/AbortController，慢旧响应不能覆盖新选择；同run更新保留缩放、路径显隐和时区。

依据必须来自本次冻结资料：归档与实际输入长度、K线截止、OI/funding、日历使用情况、原始概率、历史b、lambda、最终概率、案例列表。删泛化免责声明，保留真实缺数、失败和等待到期信息。

索引保存publication/evaluation版本信号及production/shadow角色。它是定位缓存，不替代原始证据。列表分页默认30；无变化轮询不全量读raw/重算全部评分。服务首次读取、内容变化或缓存到期按约定重验，显示 `verified_at`。

缓存不能仅凭不变的manifest永久信任其子文件；本地文件协议不是物理不可变存储。选中档案使用有界验证缓存和失效策略；学习、晋级、备份恢复必须走严格内容校验。每天核新增、每周全量审计；无法读取的单个run独立报错，不导致整个历史列表消失。

测试10/100/1000条SYNTHETIC历史，记录冷/热读取耗时及文件读取数；关键标准是热轮询不随历史总量重算全部raw，且变更、缺失、坏档与新revision可以正确刷新，不以未测量的性能倍数验收。

## 9. 备份、恢复和外部核对

### 9.1 备份覆盖完整引用闭包

备份包括原始行情分页、事件/OI/funding响应、所有forecast输入/attempt/publication、outcomes、案例/反馈快照、实验计划/决定、必要运行记录、安装/release信息和任务配置快照。不只拷贝forecast-runs而漏掉它引用的data-source。

先用短业务写锁捕获已提交对象集合和可更新指针的快照，释放后复制不可变对象；大文件复制不长期占生产锁。活跃日志先保存稳定快照或明确排除未提交尾部，不能把复制中变化的文件标为校验成功。新对象先进入备份临时区，验证hash后提交，最后提交快照manifest。

使用普通独立复制，或支持时使用具有独立文件身份的CoW复制；不可把生产文件硬链接到备份。Node可用COPYFILE_EXCL避免覆盖，并可尝试COPYFILE_FICLONE后回退普通复制，但仍要自行完成临时区校验和提交。[R9]

### 9.2 备份位置和删除保护

备份目标在生产根之外。安装时核实挂载点与文件系统身份；每日检查，外部磁盘未挂载时拒绝创建替代目标。同盘独立副本用于误操作恢复，不代表防整盘故障；要验收磁盘故障恢复，必须有独立磁盘或已授权的其他备份位置。

无合适外部目标时仍可建立标注为local-recovery的副本，但交付记录“外部故障域备份未接通”。不擅自租云存储或上传原档。

初版不自动删除原始证据、不启用复杂备份垃圾回收。容量和增长量每日汇报；低于配置安全余量时停止非必要测试/影子/大备份，并明确生产写入能否继续。备份保留策略要在实际空间与恢复验证后单独确定，不能默认循环覆盖唯一副本。

### 9.3 恢复验收

每周从已完成快照恢复到空的隔离目录：重验完整引用、读出原预测、重算已知评分、重建索引和学习摘要。全量审计或恢复超预算时保存游标并标未完成，后续备份轮继续；不能把部分审计写成最近一次全量成功。恢复不自动恢复旧活动锁、running身份或官方调度启用状态；要重新绑定目标环境。

恢复测试必须包含“删除源沙盒对象”和“修改源沙盒对象”，备份仍能还原原字节。生产原档不作为删除演练对象。

### 9.4 远端哈希核对

默认本地生成周汇总清单根，不要求业务任务提交Git。需要远端锚定时，仅在明确允许公开摘要的前提下，通过普通PR提交不含路径/样本详情的周聚合根。它证明远端曾保存过该摘要，不证明原数据真实性，不是备份或可信时间戳。禁止每轮在业务运行内git commit/push真实或细粒度运行账本。

## 10. GitHub管理、提交和审查

### 10.1 任务与分支

使用一个本轮父Issue和三个里程碑检查块：证据安全、稳定运行、数据与学习。确有独立依赖才拆少量子Issue，不为每个字段建单。每项记录范围、task_version、依赖、验收、当前提交和唯一下一动作。

先按当前实际AGENTS继续当前实现分支/PR，补齐其真实工程状态与必要CI；基线由维护者审查并合并后，采用单主干短分支：

```text
main                         已通过检查的集成基线
fix/<issue>-<topic>           修复
feat/<issue>-<topic>          有界功能
chore/<issue>-<topic>         维护与依赖
```

同一开发checkout只有一个写入者。安装包不是另一个Git工作树。不开长期develop/release分支、不强推、不覆盖他人未提交改动。切分支/更新前检查工作区和远端；不能为了同步自动reset。

AGENTS和执行器中的实际交付绑定应跟随获准Issue/PR，不把PR #7或某个分支永久硬编码为所有后续任务入口；调整只限必要绑定逻辑，保留原放行证据验证。

### 10.2 提交和PR规范

提交使用 `fix(runtime): ...`、`feat(learning): ...` 等主题，一个提交表达一个完整可检查的逻辑点，包含相关测试和必要文档。明确git add本轮文件，不使用不加区分的全量暂存。

每个PR写明：关联Issue、目标和不做项、变更文件、契约/迁移影响、测试命令及退出码、CI与tested SHA、真实验证范围、回退办法、尚未验证项。代码、脱敏测试、合成fixture可入Git；原始模型内容、真实行情/截图和本机绝对路径不上传。

草稿PR可持续更新；准备完成后转Ready for review。不能把“测试通过”当作独立审查，也不能把代理自己的进度报告当作维护者批准。

### 10.3 审查与合并规则

main要求通过实际已部署的必要CI检查、解决审查讨论，禁止普通直接push和force push。保护规则必须实际设置并回读；权限不足时明确未配置，不声称文档约定已变成技术保护。

独立审查可由另外一个只读Codex会话执行，检查当前精确head及相关依赖；已有官方GitHub审查集成可复用，不为审查引入新API。审查结论保留发现、严重性、修复提交和复验，不只写LGTM。

重点检查：写入/删除边界、互斥与孤儿进程、时间截止、失败重试、旧档兼容、原概率到发布概率关联、数据时间可用性、评分金样、CI是否依赖私有数据、回退是否可读新档。

个人单维护者仓库不要设置一个永远无法满足的“作者自己批准PR”条件：GitHub不允许PR作者批准自己的PR。[R10] 2026-09-16用户直接授权“合并，项目以后可以自行合并”。采用必要CI + 独立代码审查报告 + 已批准产品范围，官方Codex可按持续授权合并精确head，无需逐PR重复请求合并批准；确有另一位合格维护者时再设置至少一份正式批准审查。

使用squash merge形成清晰主线，官方Codex可在上述持续授权范围内执行；不直接push main、不强推。正式包激活/恢复业务仍须对应精确批准，不能从合并授权推导。新提交使相关审查/验证需要更新，不能沿用不对应当前内容的旧通过。

## 11. 本地开发、PR、CI到部署的完整流程

| 步骤 | Codex具体动作 | 进入下一步的验收标准 |
|---|---|---|
| 1. 开工核实 | 读AGENTS/当前Issue/规格；核本地与远端HEAD、工作区、PR、任务绑定；只读盘点现有归档 | 范围和实现分支明确；未覆盖外来修改；有现场差异记录 |
| 2. 保护现场 | 先建独立备份和旧档回放清单；核实遗留锁，不先运行危险默认测试 | 备份manifest和抽样恢复通过；未知活动进程未被终止 |
| 3. 最小实现 | 按依赖逐模块修改；先补失败复现测试；必要拆分超长UI入口 | 新功能非占位；正/反用例齐备；不扩大本轮范围 |
| 4. 本地自测 | 独立证据根、临时数据、空闲端口；类型/单元/集成/相关浏览器；发布前全量回归 | 退出码真实；旧证据不变；失败已解决；.mjs测试未遗漏 |
| 5. 提交与PR | diff检查、秘密/原档扫描、显式暂存、commit/push，绑定Issue和tested SHA | 远端收到对应提交；PR完整；不存在真实LOCAL_ONLY文件 |
| 6. CI | 干净checkout、锁定安装、合成数据、运行包与浏览器测试 | 所有必需job成功；不能因跳过或continue-on-error冒充通过 |
| 7. 代码审查 | 独立只读审查；逐条修复并重跑受影响测试 | 阻断性问题清零或有维护者明确接受的理由；报告绑定最新head |
| 8. 合并 | 按持续授权核验精确head并squash合并；回读实际main提交和合并后CI | 主分支实际检查通过；squash后的SHA与PR head区别被记录 |
| 9. 制作release | 从该精确已批准提交构建dist；独立运行依赖安装；闭包与哈希校验 | 移开开发src/scripts/node_modules的沙盒里仍能运行包及显示 |
| 10. 本地部署 | 短维护窗口、备份安装状态、等待活动写者结束；切release和展示服务；保持暂停意图 | 当前指针、服务/API release一致；完整性/旧档回放通过；失败可回旧包 |
| 11. 真实单轮 | 合法当前slot下实际取行情和Codex生成；核对磁盘/API/页面 | 同一run、输入截止、发布概率和release一致；及时资格真实，未重复生成 |
| 12. 调度验证 | 回读更新/新建任务；观察真实自然触发，验证ops和backup | 至少两期自然预测证据及ops/backup实际结果；无证据项如实待验证 |
| 13. 学习验证 | 真实成熟run→重算评分→案例→后续候选冻结输入 | 这条链有真实对象；尚未达到前向门槛不虚报晋级 |

没有发生的自然周期不能在当前报告中伪造；实现和部署完成后由已接通任务积累证据，不让开发会话持锁等待。

### 11.1 CI具体检查

固定四个对外检查名：`quality`、`runtime-package`、`browser`、`ci-required`。最后一个必须检查所有依赖job真实成功，不因always运行而默认成功。功能分批接入时只把已存在且真实运行的检查设为required。

**quality**：核实锁文件、typecheck、全部现有Vitest/Node分组、executor、学习/数据适配/存储新增测试、diff与跟踪文件边界、前端build。默认npm test不能代表全量。

**runtime-package**：独立安装运行依赖，检查导入闭包、无Vite运行依赖、无开发目录引用；隔离启动业务和HTTP、旧档compat回放、依赖修改检测、原子切换/回退、并发与中断测试。

**browser**：合成fixture，独立端口/证据根，真实Canvas、DPR、路径/阶段/实际线、最新与历史、同run revision刷新、坏档、竞争响应、BFCache、只读及XSS文本验证。CI Chromium通过不替代本机系统Chrome专项。

**ci-required**：汇总前述job以及必要的文件清单状态；失败或取消不可作为成功。证据文件名含workflow run ID/attempt/SHA，CI仅上传合成测试材料，默认保留14天，失败trace保留并说明。

Node、npm与依赖按本项目验证版本固定，不在CI临时升级latest。官方Actions引用实施时核实的完整commit SHA，不编造占位SHA。CI使用最小contents:read权限，不给PR真实账户、模型登录或本机磁盘访问；不在处理未信任PR时使用带写权限的pull_request_target执行其代码，不把个人Mac注册成运行公共PR的自托管runner。

每个job设置合理硬超时，起步quality 15分钟、runtime-package 15分钟、browser 20分钟。基础设施故障可以明确重跑；断言失败不能自动重跑直到变绿。发现flaky保留首次失败，修复或记录阻断，不以重试隐藏。

每周workflow的schedule只用于非实时维护。GitHub说明schedule可能延迟或丢弃，且仅对默认分支运行；因此它不承担预测时钟。[R11]

### 11.2 部署与回退操作

从确切main SHA生成包；不可用“当前目录里大概相同的代码”替代。发布审查绑定可审查内容和候选包，目标Mac安装后的平台依赖清单、hash和冒烟结果再记录为installation receipt。

切换前停止接收新的生产写任务，等已有合法轮次结束；不停止无关项目。短锁下原子更新current.json，启动同release展示服务。正常运行包内部仍禁止任意源码/data软链接；current指针是经验证的配置，不是绕过路径校验的入口。

服务启动失败、API契约不兼容或新包完整性失败，回到最近已验证且能读取现存格式的运行包；不删除新发布过的原档。策略回退与代码回退分开记录，不能用切策略伪称回退了代码。

稳定服务允许按安装配置自动启动；ops仅在确认为自己的服务已退出时有界重启，30分钟内最多3次。端口被未知进程占用不杀进程、不换端口。服务暂停状态独立于预测暂停。没有守护进程/系统调度时，启动恢复依赖下一次已定义的官方ops入口，不承诺即时自愈。

### 11.3 不可省略的验收矩阵

| 风险 | 必须实际验证 |
|---|---|
| 覆写/删除 | 两次默认测试、并发、坏路径、直接npx启动均不损坏既有证据；备份可恢复沙盒被删/改文件 |
| 运行隔离 | 开发目录修改/移走/重装不影响固定运行包；发布依赖完整且可核验 |
| 互斥 | 同时两个入口仅一写者；未知端口可见；SIGTERM/SIGKILL后不重复发布、不放任未确认孤儿 |
| 状态 | LOCK_BUSY、MUTEX_CONFLICT、PAUSED、失败、未观察到触发分别显示；旧成功不覆盖最近失败 |
| slot/时间 | 重复thread/不同release同slot仍去重；首节点相等判late；延迟/休眠不回填过去预测 |
| 数据 | 未收盘/缺口/重复冲突；OI单位、funding实际结算时点、日历零事件/来源失败/DST/日期精度 |
| 模型 | 显式配置与审计一致；缺身份不造身份；工具事件拒绝；最大attempt和截止有效 |
| 兼容 | 已知旧预测/评分仍可校验；未知版本不学习；源码重构不重写原manifest |
| 概率与路径 | Brier手算0、2、0.195、1.195；lambda=0恒等；同终点不同路径可区分；不事后挑线 |
| 防泄漏 | 追加未来才可用案例或修订未来标签，不改变过去冻结的反馈/参数；两方法看同一市场快照 |
| 学习污染 | 错误/禁用revision不入案例；kill-switch对下一输入有效；旧反馈字节保留 |
| 对照 | 失败分母保留；只在唯一检查点评价；护栏拒绝、生效下一轮、回退不反复振荡 |
| 页面 | 新run和新revision自动更新；历史不被抢走；raw/目录/脚本不得通过HTTP泄漏 |
| 调度 | 实际任务ID/配置回读；manual不冒scheduled；无任务重复；日志/告警去重和恢复可见 |

## 12. 实施顺序与交付清单

### 阶段A：证据安全与基础CI
